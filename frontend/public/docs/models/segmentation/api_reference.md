# OCT Inference Output: Frontend Integration Guide

This guide explains how to consume the JSON payload generated by the OCT segmentation backend. The data is structured using an object-oriented approach to make it extremely easy to build rich, interactive UI overlays (like tooltips, toggles, and vector layers).

## The JSON Payload Structure

The backend responds with an `OCTScanAnalysis` object, which has the following root structure:

```json
{
  "image_width": 512,
  "image_height": 512,
  "layers": [ ... ],
  "lesions": [ ... ],
  "clinical_metrics": { ... },
  "model_version": "unet_hierarchical_v1.0"
}
```

### 1. `layers` (Continuous Anatomical Boundaries)
This array contains `RetinalLayer` objects representing smooth, continuous splines across the retina (e.g., the ILM or RPE). 

**Key Fields**:
- `class_name`: A string identifier (e.g., `"ILM"`, `"RPE"`).
- `boundary_points`: An ordered array of `{x, y}` coordinates from left to right.
- `avg_depth`: The average vertical position of the layer.

**Frontend Usage**: 
You can draw these as standard SVG `<path>` elements or HTML5 `<canvas>` lines.
```javascript
// Example Canvas Drawing
ctx.beginPath();
ctx.moveTo(layer.boundary_points[0].x, layer.boundary_points[0].y);
layer.boundary_points.forEach(pt => ctx.lineTo(pt.x, pt.y));
ctx.strokeStyle = "rgba(0, 255, 0, 0.8)";
ctx.stroke();
```

### 2. `lesions` (Discrete Pathologies & Fluids)
This array contains `LesionInstance` objects. If a scan has 3 disconnected pockets of fluid, this array will contain 3 distinct objects.

**Key Fields**:
- `class_name`: The pathology type (e.g., `"Fluid"`, `"Soft Drusen"`).
- `polygon`: An ordered array of `{x, y}` points forming a closed loop around the lesion.
- `bounding_box`: Contains `xmin`, `ymin`, `xmax`, `ymax`. Use this to auto-zoom or snap the camera to the lesion.
- `area_pixels`: The size of the lesion.

**Frontend Usage**:
You can map the `polygon` points to an SVG `<polygon>` or fill it on a canvas. You can also attach an `onMouseOver` event to the bounding box to pop up a tooltip showing the `area_pixels`!

```javascript
// Example Polygon Fill
ctx.beginPath();
ctx.moveTo(lesion.polygon[0].x, lesion.polygon[0].y);
lesion.polygon.forEach(pt => ctx.lineTo(pt.x, pt.y));
ctx.closePath();
ctx.fillStyle = "rgba(255, 0, 0, 0.4)";
ctx.fill();
```

### 3. `clinical_metrics` (Global Aggregates)
A dictionary of global, scan-wide statistics pre-calculated by the backend.

**Key Fields**:
- `average_retinal_thickness`: The mean distance between the ILM and RPE.
- `total_fluid_area`: The combined sum of all fluid lesion areas.
- `max_fluid_height`: The tallest single instance of fluid.

> [!TIP]
> Use the `clinical_metrics` object to populate a high-level "Dashboard" or "Summary panel" next to the image!

## Best Practices

> [!IMPORTANT]
> **Scaling**: The coordinates provided in `boundary_points` and `polygon` are strictly relative to the original `image_width` and `image_height` (usually 512x512). If your frontend renders the image at a different size (e.g., 1024x1024), you **must** apply a scaling factor to every `{x, y}` coordinate. 
> `scale_factor_x = render_width / image_width`
